C++20 LLM orchestration.
Offline. Secure. Native.

chaincpp is a C++ library for LLM inference, agents, and RAG that runs fully offline on low-spec hardware. It embeds llama.cpp, optionally calls OpenAI or Anthropic, and treats security as a first-class primitive — not an afterthought.

Built for C++ shops

LLM features without a Python runtime.

Game studios, robotics teams, trading systems, and desktop apps need modern LLM orchestration primitives. Shipping a Python runtime to get them is not an option. chaincpp is built for exactly that.

01

Offline inference

Loads quantized GGUF models via embedded llama.cpp. Verified on an Intel i3 with 8GB RAM at 25–35 tokens per second.

02

Security as a primitive

TLS verification, secure_string with memory locking, ReDoS-safe prompt injection filter, sandboxed tool execution.

03

Familiar API shape

If you've used LangChain in Python, you already know chaincpp. PromptTemplate, ReActAgent, typed messages.

04

Multiple backends

Local via llama.cpp, or remote via OpenAI, Anthropic, and OpenRouter. All behind one BaseLLM interface.

05

Stable C ABI

c_api.h exposes a stable interface for Python, Rust, or JavaScript bindings — without writing FFI glue yourself.

06

CMake native

Works with vcpkg, FetchContent, and Ninja. A single CMake package dependency in your existing build.

What works, what doesn't

Honest about what's ready and what's coming.

Every library has limitations. Hiding them costs developers time. These are ours, stated upfront so you can decide whether chaincpp fits your project today.

Works today (v0.1.0-alpha)

  • ✓ Local GGUF inference via llama.cpp b4242
  • ✓ OpenAI, Anthropic, OpenRouter remote backends
  • ✓ Prompt templates with injection filter
  • ✓ ReAct agent loop with PIMPL isolation
  • ✓ TextSplitter for document ingestion
  • ✓ C ABI for cross-language bindings
  • ✓ Sandbox with cooperative timeouts
  • ✓ Linux OS-level memory enforcement (RLIMIT_AS)

Not yet (roadmap)

  • · Persistent vector database — target v0.2
  • · Python bindings via pip — target v0.2
  • · GPU auto-offload — target v0.2
  • · seccomp-bpf (Linux) and Job Objects (Windows)
  • · macOS sandbox is best-effort only (Mach kernel limitation)
  • · llama.cpp pinned to b4242 — upgrade planned
Getting started

Three commands to a working demo.

Requires CMake 3.20+, a C++20 compiler, libcurl, and nlohmann_json. The local demo runs fully offline — no API key required.

1

Clone and download the model

git clone https://github.com/Toyse-dev/chaincpp.git
cd chaincpp

mkdir -p models
curl -L -o models/tinyllama.gguf \
  https://huggingface.co/TheBloke/TinyLlama-1.1B-Chat-v1.0-GGUF/resolve/main/tinyllama-1.1b-chat-v1.0.Q4_K_M.gguf
2

Build with CMake

cmake -B build -G Ninja \
  -DBUILD_TESTS=ON \
  -DCMAKE_BUILD_TYPE=Release

cmake --build build -j2
3

Run the offline demo

./build/examples/local_example
